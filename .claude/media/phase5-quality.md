# Phase 5: 品質チェック

```
【インプット】
- progress.json: { "phase": "write_done" }
- articles/draft_{article_id}.md

【アウトプット】
- articles/final_{article_id}.md
- progress.json 更新: { "phase": "quality_done", "quality_score": 97 }

【完了条件】
- 5視点合計スコアが95点以上
- articles/final_{article_id}.md が存在すること
```

> ⚠️ **役割切り替え（重要）**
> このPhaseに入る前に必ず宣言する:
> 「あなたはPhase 4で記事を書いたエージェントとは完全に別の存在です。
> 今から厳格な編集長として振る舞い、この記事を初めて読む視点で採点してください。
> 執筆プロセスへの配慮は一切不要。読者の利益のみを基準に採点すること。」

## 実行手順

1. **メタ情報設定**
   - タイトル: 30文字以内・KWを先頭・数字を含める
   - メタディスクリプション: 120文字以内

2. **E-E-A-T注入** / **内部・外部リンク** / **GEO/LLMO構造対応**
   - 内部リンク: 3-5本 / 外部権威ソース: 3-5本 / FAQ 5問以上

3. **5視点採点（各20点 / 合計100点）**

   **視点1: デザイン【20点】**（各2点）
   - H2構成が目次に対応し各H2冒頭に1文結論があるか
   - テーブルのヘッダー・スタイルが統一されているか
   - CTAが2箇所以上で配置されているか
   - H2直下に図解画像が配置されているか
   - テキスト強調（strong）が12-18箇所に適切に配置されているか
   - 段落が3行以内で読みやすいか
   - 箇条書きの前後にリード文があるか
   - プロンプト例がコードブロック形式で掲載されているか
   - 画像にaltテキストが設定されているか
   - 全体のフォーマットが統一されているか

   **視点2: SEO【20点】**（各2点）
   - タイトルにKWが自然に含まれているか・30文字以内か
   - メタディスクリプションが120文字以内で検索意図を満たすか
   - 本文が5,000文字以上あるか
   - 各H2冒頭に1文結論（GEO対応）があるか
   - 外部リンクが権威あるソースに設定されているか
   - E-E-A-T要素（著者実績・数値・一次情報）が含まれているか
   - FAQセクションが5問以上あるか
   - 内部リンクが3本以上あるか
   - KWの検索意図と記事構成が一致しているか
   - 独自ファクトが3箇所以上あるか

   **視点3: 編集（文体）【20点】**（各2点）
   - AI感のある表現が排除されているか（quality-rules.md の7項目チェック）
   - ですます調で統一されているか
   - リード文が2-3文で簡潔か
   - 一人称の体験談・観察が2箇所以上あるか
   - X/YouTube引用がインラインで自然に組み込まれているか
   - 専門用語が初出時に平易に説明されているか
   - 1文50字以下・段落3行以内が守られているか
   - 文末パターンにバリエーションがあるか
   - 体言止めが2-3箇所あるか
   - 「この記事でわかること」ボックスが冒頭にあるか

   **視点4: 技術正確性【20点】**（各2点）
   - ツールの説明が正確で最新か
   - プロンプト例が実用的か（コピーして即使用可能）
   - ワークフロー手順が初心者でも再現できる粒度か
   - 専門概念が平易に説明されているか
   - ツールの限界・注意点が正確に記載されているか
   - 導入事例の数値が具体的で信頼性があるか
   - 比較情報が正確か（料金・機能・対応状況）
   - 「次に試すべきアクション」が具体的か
   - 最新動向と記事内容に齟齬がないか
   - ユースケースが具体的か（業務・入力・出力）

   **視点5: 読者UX（ペルソナ: 中小企業経営者・ITリテラシー中程度）【20点】**（各2点）
   - リード文で「自分の悩みに答えてくれる」と感じられるか
   - 専門用語が初出時に説明されているか
   - 各H2の結論を読むだけで得られるものが分かるか
   - 導入事例が「自分でも再現できそう」と感じられるか
   - 「まず何から始めるか」が明確か
   - 段落が3-4文以内で読みやすいか
   - 表が単体で意味が完結しているか
   - FAQが実際にペルソナが抱く疑問と一致しているか
   - CTAが「申し込みたくなる」文脈で提示されているか
   - 読後に「次に何をすればいいか」が分かるか

4. **修正ループ**
   ```
   採点 → 合計 < 95点:
     1. 最低スコアの視点の指摘を優先修正
     2. 修正した視点のみ再採点（他のスコアは維持）
     3. 最大3サイクル繰り返す
     4. 3サイクル後も95点未満 → ユーザーに差分レポートを提出して停止
   ```

5. **状態更新**
   - `articles/final_{article_id}.md` に最終稿を保存
   - `progress.json` を更新（quality_score に合計点を記録）
