# 問題発見ビジネス創出スキル

## 概要
日常の問題や不満をビジネス機会に変換するためのフレームワーク

## 3つのアプローチ

### アプローチ1: 自己の痛み分析
自分自身の問題からビジネスアイデアを生成

**手順:**
1. 自分の痛みポイントを明確に定義する
2. 市場の既存ソリューションを調査する
3. 既存サービスが存在しない場合、ビジネス機会として検討
4. ターゲット層を拡張する

**事例: 金属アレルギー対応ECサイト**
- 問題: チタンや金以外の時計でじんましんが出る
- 現状: 専門のECサイトが存在しない
- ソリューション: アレルギー情報でフィルタリングできるECサイト
- 拡張: 銅アレルギー、ニッケルアレルギーなどにも対応

### アプローチ2: 不満解決ビジネス
既存サービスの不満から改善ビジネスを創出

**手順:**
1. 既存サービスの痛みポイントを特定
2. より良いソリューションを設計
3. 最小実行可能サービスで検証
4. 収益化モデルを構築

**事例: 最安値宿泊予約情報サイト**
- 問題: 20年前、最安ホテル情報が各サイトに散在
- ソリューション: 個人が最安予約方法を投稿するサイト
- 収益化: ユーザーベース構築後の広告収入

### アプローチ3: 身近な声ビジネス
周りの人からニッチビジネスを発見

**手順:**
1. 身の回りの人の問題に耳を傾ける
2. 同じ問題を持つ人の規模を推定
3. 専門サービスを企画
4. ニッチ市場で競争優位を構築

**事例: ジム物件専門不動産**
- 問題: スミスマシンや器具を置くと物件が借りられない
- 発見: ジム起業家に共通の問題
- ソリューション: ジム物件専門の不動産業
- 結果: 専門性により売上向上

## 実装手順

### 1. 問題定義手法
- 具体的な痛みポイントを書き出す
- 頻度と深刻度を評価する
- 他の人も同じ問題を抱えているかを確認する

### 2. 市場規模調査プロセス
- 類似サービスをGoogle検索
- SNSで同じ問題を持つ人を探す
- 関連コミュニティでインタビュー実施

### 3. MVP作成ガイドライン
- 最小限の機能で仮説を検証
- 手動プロセスでも早期リリース
- ユーザーフィードバックを収集

### 4. 収益化タイミング
- ユーザーが価値を感じ始める時期を見極める
- 適切なモデルを選択：広告、手数料、サブスクリプション
- ユーザー離れを防ぐための段階的収益化

## 事例分析

### 成功パターン
1. **ニッチな問題**: 一般的ではないが確実に存在する問題
2. **不完全な既存ソリューション**: 完璧ではないサービス
3. **専門知識の活用**: 業界特有の洞察
4. **継続改善**: ユーザーフィードバックに基づく進化

### 注意点
- 個人的な問題だけでないことを検証
- 市場規模が小さすぎないことを確認
- 技術的実現可能性を考慮
- 法規制やライセンス要件をチェック

## 出力指示

このスキルを使用する際は、包括的な分析レポートを生成し、以下の形式で`business-ideas/`ディレクトリに.mdファイルとして自動保存してください：

**ファイル名形式:** `[日付]_[時刻]_[問題キーワード].md`

**コンテンツ構造:**
```markdown
# ビジネスアイデア分析レポート

## 問題定義
[具体的な問題の説明]

## アプローチ分析
[3つのアプローチのどれを使用したかと理由]

## 市場調査結果
[既存ソリューションと市場ギャップの調査結果]

## 提案ソリューション
[詳細なソリューション提案]

## ターゲット拡張
[拡張されたターゲット層の分析]

## 実装ロードマップ
[段階的な実装計画]

## リスク評価
[潜在的リスクと軽減策]

## 成功確率評価
[成功確率の評価と根拠]
```

これにより、すべてのビジネスアイデア分析が適切に文書化され、将来の参照に容易にアクセスできるようになります。
