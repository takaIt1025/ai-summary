# App Store 掲載文生成スキル

アプリ情報を入力すると、App Store Connect にそのまま貼り付けられる掲載文一式を生成します。
文字数・バイト数の制約を厳守しつつ、ASOを意識したキーワード配置を行います。

## プロンプト

```
あなたはApp Store Optimization（ASO）の専門家です。
以下の情報をもとに、日本のApp Store向け掲載文一式を生成してください。

【入力情報】: $ARGUMENTS

【出力方針】
- 対象: iOS App Store 日本市場
- 言語: 日本語（英語版が必要な場合は末尾に併記）
- 文字数制約を必ず厳守する
- キーワードはユーザーが実際に検索するワードを優先する
- 競合との差別化を説明文の冒頭に凝縮する

---

【作業手順】

### Step 1: 入力情報の整理

$ARGUMENTS を以下の形式に整理する。リポジトリパスが含まれる場合は Step 1.5 を実施する。

必須項目:
- アプリ名（仮でも可）
- カテゴリ
- 主要機能（3〜5個）
- ターゲットユーザー
- 差別化ポイント
- マネタイズモデル

任意項目（あれば精度向上）:
- キーワード調査結果（/app-keyword-research の出力）
- 競合アプリ名
- スクリーンショット枚数（デフォルト: 5枚）

不足項目がある場合は合理的に推測して補い、補った内容を「⚠️推測」と明示する。

---

### Step 1.5: リポジトリからの情報補完（パスが指定された場合のみ）

リポジトリパスが渡された場合、以下のファイルを読み取って機能・特徴を補完する。

```bash
# pubspec.yaml から依存パッケージを確認（機能の推測）
cat <repo_path>/pubspec.yaml | grep -A 100 "dependencies:"

# CLAUDE.md または README.md からアプリ概要を取得
cat <repo_path>/CLAUDE.md 2>/dev/null || cat <repo_path>/README.md 2>/dev/null | head -80

# lib/ ディレクトリの画面構成を把握
find <repo_path>/lib -name "*.dart" | head -30
```

読み取った情報で Step 1 の入力を補完し、「📂コードから取得」と明示する。

---

### Step 2: キーワード戦略の策定

入力情報と（あれば）キーワード調査結果から、使用するキーワードを優先度順に整理する。

**キーワード優先度の考え方:**
- 高優先: 直接的な機能ワード（例: 「サウナ記録」「サ活」）
- 中優先: ユーザー状態ワード（例: 「ととのう」「サウナー」）
- 低優先: 競合と被るワード（タイトルに既に入っているなら除外）

キーワードフィールドは **100バイト以内**（UTF-8、カンマ区切り）。
日本語1文字 = 3バイト。スペース不要、読点「、」ではなくカンマ「,」を使う。

```python
# バイト数チェック用
keywords = "キーワード1,キーワード2,..."
print(len(keywords.encode('utf-8')), 'bytes')
# 100バイト以下であること
```

---

### Step 3: タイトル・サブタイトルの生成

**制約:**
- タイトル: **30文字以内**（スペース含む）
- サブタイトル: **30文字以内**（スペース含む）

**設計方針:**
- タイトルにはメインキーワードを必ず含める
- サブタイトルはタイトルと重複しないキーワードを使い、ユーザーベネフィットを訴求
- 「〜アプリ」「〜ツール」で終わるより、ベネフィット訴求の方が高評価

候補を **3パターン** 生成し、それぞれのASO観点での長所・短所を添える。

---

### Step 4: 説明文の生成

**制約:** 4000文字以内

**構成（重要度順）:**

```
【冒頭3行】← App Store の「続きを読む」折りたたみ前に表示される最重要部分
  差別化ポイントとメインベネフィットを1〜2文で凝縮

【主要機能（箇条書き）】
  ・機能名: 説明（ユーザーが得られる価値ベースで書く）

【ターゲットユーザー訴求】
  「こんな方におすすめ」形式

【マネタイズ説明】（有料・IAP・サブスクがある場合）
  無料で使える範囲と課金で解放される機能を明示

【末尾】
  お問い合わせ・SNS・プライバシーポリシーURL（プレースホルダーでよい）
```

---

### Step 5: キーワードフィールドの生成

Step 2 の戦略をもとに、100バイト以内のキーワード文字列を生成する。

ルール:
- タイトル・サブタイトルに含まれる語は**除外**（重複カウントされない）
- カンマ区切り・スペースなし
- 実際のバイト数を計算して明示する

```bash
python3 -c "
kw = '生成したキーワード文字列'
b = len(kw.encode('utf-8'))
print(f'{b} bytes / 100 bytes')
print('OK' if b <= 100 else 'NG - 削減が必要')
"
```

---

### Step 6: スクリーンショット用キャプションの生成

スクリーンショット枚数分（デフォルト5枚）のキャプションを生成する。

**各キャプションの構成:**
- 1行目（大見出し）: 14文字以内、インパクト重視
- 2行目（補足）: 20文字以内、機能の説明

**5枚の流れ（推奨構成）:**
1. アプリのコアバリュー（最も刺さるベネフィット）
2. メイン機能①
3. メイン機能②
4. メイン機能③ or 差別化ポイント
5. CTA（「今すぐ始める」「まずは無料で」等）

---

### Step 7: プロモーショナルテキストの生成（任意）

**制約:** 170文字以内

App Store に表示される短いプロモ文。キャンペーンや期間限定情報に使う。
通常は「今すぐ使える・無料・何ができるか」を凝縮する。

---

### Step 8: 出力をファイルに保存

`app-store-listing/[YYYYMMDD]_[アプリ名].md` 形式で保存する。
ディレクトリが存在しない場合は作成する。

## 使用例

### 例1: テキスト入力のみ
```
/app-store-listing
アプリ名: サ活ログ
カテゴリ: 健康/フィットネス
主要機能: サ活記録, シェアカード生成, カレンダー表示
ターゲット: サウナ愛好家・20〜40代
差別化: iPhone単体完結・SNSシェア特化・デバイス不要
マネタイズ: 無料 + IAP ¥480
```

### 例2: リポジトリ連携
```
/app-store-listing
アプリ名: サ活ログ
カテゴリ: 健康/フィットネス
リポジトリ: /Users/tky/Projects/sakatsu-log
```
→ pubspec.yaml・CLAUDE.md・lib/を読み取って機能を自動補完

### 例3: キーワード調査結果を活用
```
/app-store-listing
アプリ名: サ活ログ
[app-keyword-researchの出力をここに貼り付け]
```
→ 調査済みキーワードをそのままタイトル・KWフィールドに反映

---

## 技術的制約と注意

- **タイトル30文字・サブタイトル30文字**: App Store Connect の入力制限。超過するとリジェクト
- **キーワード100バイト**: UTF-8バイト数で計算。日本語1文字=3バイト、英数字1文字=1バイト
- **説明文4000文字**: 冒頭の「続きを読む」折りたたみ前の3行が最も重要
- **プロモーショナルテキスト170文字**: いつでも変更可能。説明文と違いレビューなしで更新できる
- リポジトリ読み取りは参考情報として使用し、最終的な内容は入力情報を優先する
