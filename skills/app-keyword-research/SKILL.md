# iOSアプリキーワード調査SKILL

完全無料のAPI/エンドポイントのみを使用して、日本のApp Storeを対象としたキーワード調査と競合分析を行います。

## プロンプト

```
あなたはASO（App Store Optimization）の専門家です。
以下のキーワードについて、日本のApp Store（iOS）を対象にキーワード調査と競合分析を行ってください。

【調査対象キーワード】: $ARGUMENTS

【調査方針】
- 対象プラットフォーム: iOS（App Store）
- 対象地域: 日本（country=jp）
- 使用ツール: 完全無料のAPI/エンドポイントのみ
- 出力言語: 日本語
- 複数キーワードが渡された場合は、横断比較セクションを必ず含める

【作業手順】

### Step 1: 別表記の自動展開
まずキーワードに以下の別表記が存在する場合、追加で調査対象に加える:
- カタカナ⇄ひらがな⇄漢字（例: マンダラチャート / まんだらチャート / 曼荼羅 / マンダラート）
- 英語名・略称（例: Mandala / 9マス）
- 半角⇄全角（例: 9×9 / 9x9）

判断に迷う場合はGoogle Suggestで「<キーワード>とは」「<キーワード> 別名」を確認してから決める。

### Step 2: iTunes Search APIで競合アプリを取得
全ての（別表記含む）キーワードについて以下のcurlを実行し、競合アプリTOP50を取得する。
日本語のtermはURLエンコード必須（python3の `urllib.parse.quote` を使用）。

curl -s "https://itunes.apple.com/search?term=<URLエンコード済みキーワード>&country=jp&entity=software&limit=50&lang=ja_jp" | jq '.'

取得する情報:
- trackName（アプリ名）
- artistName（開発者）
- averageUserRating（評価）
- userRatingCount（評価数）
- price / formattedPrice（価格）
- description（説明文）
- genres（ジャンル）
- releaseDate / currentVersionReleaseDate（リリース・更新日）
- trackId（追加調査用ID）
- trackViewUrl（App StoreページURL）

### Step 3: Google Suggestで関連キーワードを取得

curl -s "https://suggestqueries.google.com/complete/search?client=firefox&hl=ja&q=<URLエンコード済みキーワード>" | python3 -c "
import sys, json
raw = sys.stdin.buffer.read()
for enc in ['utf-8', 'cp932', 'shift_jis', 'euc-jp']:
    try:
        data = json.loads(raw.decode(enc))
        for s in data[1]:
            print(s)
        break
    except Exception:
        continue
"

# 重要: client=firefox は Shift-JIS (cp932) で返ることがある。
# UTF-8デコード失敗時に必ず cp932 等のフォールバックを行う。

実用的なサジェスト接尾辞（あ〜ん全件は冗長で意味が薄い。以下が実戦で有効）:
- "アプリ" / "無料" / "おすすめ" / "iphone" / "ipad" / "mac" / "android" / "pc"
- "使い方" / "作り方" / "書き方" / "やり方" / "テンプレート" / "例"
- "とは" / "効果" / "コツ" / "本"
- 業界の有名人・由来（例: マンダラチャートなら「大谷」「大谷翔平」）
- ジャンル別カテゴリ語（例: 習慣化なら「かわいい」「ゲーム」「勉強」）

### Step 4: App Store Suggest（補助・任意）
非公式エンドポイント。動かないこともあるので失敗しても続行する。

curl -s "https://search.itunes.apple.com/WebObjects/MZSearchHints.woa/wa/hints?clientApplication=Software&term=<URLエンコード済みキーワード>"

### Step 5: 説明文からキーワード頻度を集計
Step 2で取得した上位アプリの description と trackName を結合し、頻出語を抽出する（2〜6文字の連続文字を簡易TFで集計）。
ストップワード（"アプリ" "機能" "簡単" "できます" など一般語）は除外する。

### Step 6: 競合強さの定量評価
各競合アプリを以下のバケットに分類:

| レビュー数 | 評価 | 判定 |
|---|---|---|
| 10,000以上 | 4.5以上 | **超強敵** ★★★★★ |
| 1,000〜9,999 | 4.5以上 | 強敵 ★★★★ |
| 100〜999 | 4.0以上 | 中堅 ★★★ |
| 10〜99 | 4.0以上 | 弱小だが要注意 ★★ |
| 10未満 | - | 無視可（ただし新参で勢いがあれば注視）★ |

加えて以下も加味:
- 直近1年以内の更新 = アクティブで継続投資中
- 直近2年以上更新なし = 放置されている可能性 → 攻略チャンス

### Step 7: 自社アプリの特定（指定があれば）
ユーザーから「自分のアプリ名」または「自分の開発者名」が示されている場合、または検索結果に明らかにユーザー本人のアプリが含まれる場合、そのアプリの**現在地と改善余地**を専用セクションで詳述する。
- 検出方法: trackName または artistName をユーザーの GitHub username / 提示された開発者名と照合
- 分析項目: 現在の順位、レビュー数、評価、タイトル/サブタイトルに含まれていない重要キーワード、説明文の弱点

### Step 8: 狙い目度スコアの算出（複数キーワード時）
キーワードごとに以下を算出:
- ヒット数（少ないほど競争緩い）
- 上位5社の合計レビュー数（少ないほど狙える）
- 評価4.5以上の競合数

これらを総合して「⭐⭐⭐⭐⭐〜⭐」で5段階評価する。

### Step 9: 結果をMarkdownで保存
`keyword-research/[YYYYMMDD_HHMMSS]_[キーワード].md` 形式で保存する。
keyword-research ディレクトリが存在しない場合は作成。
複数キーワード時はファイル名を `_` 区切りで連結。
```

## 使用例

### 例1: 単一キーワード調査
```
/app-keyword-research マンダラチャート
```
→ 別表記（マンダラート、曼荼羅）も自動展開して横断分析。

### 例2: 複数キーワードでの比較
```
/app-keyword-research マンダラチャート 目標達成 習慣化 9マス思考
```
→ 各キーワードの市場混雑度を比較し、最も狙い目な切り口（狙い目スコア）を提示。

### 例3: 自社アプリの立ち位置調査
事前に「私のアプリは XX です」と伝えてから実行すると、Step 7で自社の現在地分析が含まれる。

## 技術的制約と注意

- iTunes Search APIは1分あたり約20リクエストの制限あり。連続実行時は2〜3秒待つ。
- Google Suggestは非公式エンドポイント。仕様変更の可能性あり。
- Google Suggestのレスポンスは **Shift-JIS (cp932) で返ることがある**。UTF-8/CP932/Shift-JIS/EUC-JPの順でフォールバックを必ず入れる。
- レビュー本文の取得は別エンドポイント（RSS: `https://itunes.apple.com/jp/rss/customerreviews/...`）が必要。本SKILLでは扱わない（拡張スキル `competitor-aso-analyzer` で対応）。
- 検索ボリュームの**正確な数値**は無料では取得できない。出現頻度・サジェスト有無で**相対評価**を行う。
- 「あ〜ん」「a〜z」の機械的網羅は冗長。実用接尾辞リスト（Step 3に記載）を優先する。

## 拡張アイデア

- `competitor-aso-analyzer`: 特定アプリ（trackId指定）のレビューから不満キーワードを抽出
- `keyword-difficulty-checker`: 複数キーワードの難易度マトリクス作成
- `aso-title-optimizer`: タイトル/サブタイトル候補を制約（30文字/30文字/100バイト）内で複数生成
